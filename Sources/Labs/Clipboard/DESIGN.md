# Clipboard history ("C" button + Clipboard tab): design note

## How production clipboard managers do it

| Topic | What working tools do | Source |
|---|---|---|
| Change detection | No notification exists for pasteboard changes. Maccy polls `NSPasteboard.general.changeCount` from a repeating timer, default **500 ms** (`clipboardCheckInterval`), and seeds `changeCount` at launch so it doesn't record what was already on the clipboard. | Maccy `Clipboard.swift` and README (MIT) <https://github.com/p0deje/Maccy> |
| Marker types | nspasteboard.org markers: `org.nspasteboard.TransientType` (don't record), `org.nspasteboard.ConcealedType` (confidential), `org.nspasteboard.AutoGeneratedType` (not a user copy, generally don't record), `org.nspasteboard.source` (bundle id of the source app). Proprietary types treated the same way: `de.petermaurer.TransientPasteboardType`, `com.typeit4me.clipping`, `Pasteboard generator type` (transient), `com.agilebits.onepassword` (concealed). | <http://nspasteboard.org> |
| What Maccy always ignores | Transient, Concealed and AutoGenerated are always ignored. Ignored by default, but removable: `com.agilebits.onepassword`, `com.typeit4me.clipping`, `de.petermaurer.TransientPasteboardType`, `Pasteboard generator type`, `net.antelle.keeweb`. Universal Clipboard (`com.apple.is-remote-clipboard`) is opt-out. | Maccy README; `NSPasteboard.PasteboardType+Types.swift` |
| Supported types | Maccy: `.fileURL`, `.html`, `.png`, `.rtf`, `.string`, `.tiff`. It never persists web archives, `dyn.*` or `com.microsoft.ole.source.*` types. | Maccy `Clipboard.swift` |
| Dedupe and pinning | A new copy that duplicates an existing item replaces it, keeping its pin, `firstCopiedAt` and copy count. The size limit applies only to unpinned items. | Maccy `Observables/History.swift` |
| Own writes | Maccy tags its own writes with a private type (`org.p0deje.Maccy`) and sets `org.nspasteboard.source`. | Maccy `Clipboard.swift` |
| Password managers | Raycast ignores "passwords copied from any password managers and other transient data" by default and has a per-app exclusion list. Alfred ignores Keychain Access and 1Password by default and skips Concealed data. Alfred also has a maximum clip size: text over the limit is dropped. | <https://www.raycast.com/extensions/clipboard-history>, Raycast 1.1.0 changelog, <https://www.alfredapp.com/help/features/clipboard/> |
| Concealed in the API | Raycast's `Clipboard.copy(x, { concealed: true })` writes the concealed marker that other managers check. CopyQ treats the concealed type as "secret". | <https://developers.raycast.com/api-reference/clipboard> |
| macOS pasteboard privacy | Since macOS 15.4 the system can alert the user when an app *programmatically reads* the general pasteboard (it doesn't alert on user-initiated paste). `NSPasteboard.accessBehavior` reports `.default` (never alerted yet), `.ask`, `.alwaysAllow` or `.alwaysDeny`. After the first alert the state becomes `.ask`, and the user can change it in Privacy & Security › "Paste from Other Apps". Reading other, named pasteboards always works without an alert. | Apple docs `NSPasteboard.AccessBehavior` (SDK header `NSPasteboard.h`); <https://mjtsai.com/blog/2025/05/12/pasteboard-privacy-preview-in-macos-15-4> |

## Decisions for SparkV

1. **Opt-in, off by default.** SparkV does many things besides clipboard history, so the history only starts after the user presses "Turn On" (in the tab or in the C button's menu). A press is user-initiated, so if macOS shows its one-time pasteboard alert, it appears right after the user asked for the feature and never at launch.
2. **Access gate.** Every time `changeCount` changes, the controller checks `accessBehavior`, which never reads any content:
   - `.alwaysAllow`, or a system older than 15.4: read the pasteboard.
   - `.default`: read only because the user turned the feature on. The system shows at most one alert.
   - `.ask`: don't read automatically, because every read would prompt again. Show "Allow in Privacy & Security" instead.
   - `.alwaysDeny`: don't read. Show a "denied" state.
3. **Polling.** A main-actor `Task` loop runs every 0.5 s and reads only `changeCount` (an integer). Content is read only when the count changes. Hashing, image decoding, the TIFF→PNG conversion, thumbnails and every disk write happen on a background actor (`ClipboardDiskStore`). The pasteboard itself is read on the main thread, as Maccy does, because `NSPasteboard` is not documented as thread-safe.
4. **Privacy rules, checked on the type list *before* any data is read:**
   - Concealed, Transient and AutoGenerated types are always skipped.
   - The Maccy default list of password-manager and transient types is skipped.
   - An app exclusion list is checked against `org.nspasteboard.source`, falling back to the frontmost app. The default list covers Keychain Access, Passwords, 1Password, Bitwarden, LastPass, Dashlane, KeePassXC, Enpass, Strongbox, Keeper, NordPass and Proton Pass, and the user can add apps.
   - Universal Clipboard copies are skipped when that option is on (off by default).
   - Our own writes are recognised by their change count and the `com.notchisland.clipboard` marker, and move the existing item to the top instead of making a duplicate.
   - "Pause history" lets copies go unread, and they stay unread after resume. "Ignore next copy" skips one copy.
   - "Clear" deletes the index and all blobs. Clearing keeps pinned items unless "including pinned" is chosen.
5. **Types and kinds.** In priority order:
   - File URLs become `file`.
   - A bitmap (`png`, `tiff`, `jpeg`, `heic`) with no meaningful text, or with only a URL (as Safari's "Copy Image" produces), becomes `image`.
   - A single http(s) URL becomes `url`.
   - Text that comes with RTF or HTML becomes `richText`.
   - Anything else with text becomes `text`.

   PDF-only pasteboards are not treated as images, which follows the existing TrayStore rule.
6. **Size limits.** These follow Alfred's "maximum clip size" idea:
   - Text larger than 2 MB (UTF-8) is skipped.
   - RTF or HTML larger than 4 MB is dropped, but the plain text is kept.
   - Images larger than 40 MB are skipped.
   - At most 200 file URLs are kept.

   TIFF images are stored as PNG. A 240 px thumbnail is stored separately, so the drawer never decodes a full-size image.
7. **History.** The 30 most recent unpinned items, plus up to 20 pinned ones, newest first. Dedupe uses a SHA-256 fingerprint of the content: text, rich text and URL share the plain-text fingerprint, so the same text copied twice is one item, and the newest copy wins with its pin and count carried over.
8. **Storage.** `~/Library/Application Support/SparkV/Clipboard/` with `history.json` and `blobs/`, with the directory set to mode 0700. Files are written atomically, and orphaned blobs are pruned at load. A "Keep history across restarts" switch (default on) keeps history in memory only and wipes the disk copy when turned off.
9. **Copy-back and paste.**
   - Click copies the item back with every stored representation, as Maccy does.
   - Double-click (or ⌥ in the menu, ⌥⌘1…9) pastes: the item is written with every representation, then `ClipboardPaster` posts ⌘V into the frontmost app, as Maccy does, so rich text, images and files paste as themselves. It needs Accessibility (never prompted); without it the item stays on the clipboard with a hint. "Paste as Plain Text" writes plain text only.
   - The C button pastes the *current clipboard*: when the pasteboard's change count still matches the newest history item it pastes that item; otherwise (a password, a copy made while paused, before launch) it posts ⌘V without reading or replacing anything.
   - Clear History and turning "Keep history after restart" off ask for confirmation; the card's delete button needs a second click.
   - Images get on-device text recognition (Vision, fast level), off the ingest queue, so screenshots are searchable by their words, as in Raycast.
10. **UI.**
    - The "C" capsule shows a preview of the current item.
    - Click pastes the current item. ⌥-click only copies it.
    - Click-and-hold or right-click opens a native `NSMenu`: recent and pinned items, with an ⌥-alternate "Paste" for each, plus Pause, Ignore Next Copy, Excluded Apps and Clear. A menu was chosen over an `NSPopover` because menus are reliable in a non-activating panel, and TrayView already uses them.
    - The Clipboard tab has a search field, kind filters, horizontally scrolling cards, hover pin and delete buttons, drag-out through the existing `TrayDragSource`, and a context menu.
    - Copying posts a "Copied" `LiveActivity`.

No proprietary code or assets were used. The behaviour follows public docs and Maccy's MIT-licensed source, with no code copied verbatim.

## Clipboard stack (⌘+N+V, ⌘⇧V) and smart types

How other tools do it:

| Topic | What working tools do | Source |
|---|---|---|
| Quick paste by number | Paste: ⌘1–⌘9 paste items 1–9 while Paste is open, and ⇧⌘1–9 paste them as plain text. Maccy: ⌘N selects and ⌥N pastes. Windows Win+V: a list you move through with the arrows, then Enter. | <https://pasteapp.io/help/keyboard-shortcuts>, Maccy README |
| Opening the list | Paste: ⇧⌘V shows or hides Paste (configurable). Maccy: ⇧⌘C. Raycast: a hotkey you assign. | same |
| Keys in the list | Arrows to move, ↩ to paste, typing to search, ⌥P to pin (Maccy), ⌥⌫ to delete (Maccy), Space for Quick Look (Paste). | same |
| Panel focus | A non-activating `NSPanel` that becomes key, so the app you were in stays frontmost and the paste lands there (Maccy's FloatingPanel, Raycast). | Maccy source |
| Smart types | Raycast and Paste show colour swatches and link previews. NSDataDetector finds links and phone numbers. | Apple docs `NSDataDetector` |

Decisions:

1. **The chord** (the user's request): hold ⌘, press a digit, then press V.
   - An active `CGEventTap` on its own thread holds ⌘+digit back for up to 400 ms.
   - If V arrives while ⌘ is still down, both are swallowed. The item is then written with every representation, and ⌘V is posted with the synthetic tag. If ⌘ is still physically down, only V is posted, with the ⌘ flag.
   - Anything else replays the held events in order: another key, ⌘ released, another modifier, or the timeout. Replays use `tapPostEvent` from the callback, or a session-tap post from the timer.
   - A digit is only held when the stack has that many items, so ⌘1–9 is untouched while history is off or short.
   - The logic is a pure `ClipboardChordMachine` that the harness tests with synthetic input.
2. **⌘⇧V** opens the stack, the same as Paste's default.
   - It replaces "Paste and Match Style" only while history is on and not empty.
   - It has its own off switch.
   - Pressed again inside the panel, it closes the panel.
3. **Numbers** are stack positions, newest first, and pins don't jump the queue. The C menu's ⌘1–9 entries and the tab's card badges use the same numbers, so the badge you see is the N you type.
4. **Panel**
   - **Placement:** it opens at the text caret (AX `kAXBoundsForRangeParameterizedAttribute` on the selected range, 250 ms messaging timeout, looked up off the main thread). It falls back to a small focused field, then to the pointer. It sits below the caret, flips above near the bottom of the screen, and is clamped to the visible frame.
   - **Height:** it fits 0–8 rows. Space or → opens a preview column (full image, full text, colour in every format with Copy buttons).
   - **Typing:** a letter starts a search, and so does "/" (use "/" to search for something starting with "p"). Once searching, P and Space type.
   - **Pinned items:** ⌫ on a pinned item asks for a second press.
5. **Smart types** (`ClipboardContentDetector`, pure):

   | Type | How it is detected | Action |
   |---|---|---|
   | Colour | `#rgb`, `#rrggbb`, `#rrggbbaa`, `0x…`, bare 6- or 8-digit hex that mixes letters and digits, `rgb()`/`rgba()`, `hsl()`/`hsla()` | Swatch, "Copy as RGB/HSL/HEX/SwiftUI" |
   | Path | Existing absolute, `~`, `file://`, quoted or shell-escaped paths | "Reveal in Finder" |
   | Email | Optionally prefixed with `mailto:` | "Compose" (`mailto:`) |
   | Link | NSDataDetector covering the whole string. A bare `name.ext` needs a common TLD. | "Open" |
   | Phone | 7–15 digits, with "+" or separators, and the whole string matched by NSDataDetector (dates and decimals excluded) | "Call via FaceTime" (`facetime-audio:`) |
   | Code | JSON that parses, shell commands, or a score built from symbol density, line endings, indentation and keywords, with prose penalised | Shown monospaced, with a language guess |
