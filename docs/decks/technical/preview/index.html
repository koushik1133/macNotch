Architecture

One panel, thirty-one feature objects

How a non-activating NSPanel becomes a command center

NotchPanel: borderless, non-activating, .statusBar level, on every Space

Click-through at rest; becomes key only when a control needs it

NotchWindowController owns the controllers and one shared ActivityCenter

Features live in Sources/Labs/<Feature>/ with DESIGN.md and INTEGRATION.md

Speaker notes

The whole app is one borderless, non-activating panel at status-bar level. It joins every Space, including full-screen apps, never steals focus, and lets clicks fall through while the island is closed. AppKit normally pushes windows below the menu bar, so the panel overrides constrainFrameRect to sit at the absolute top edge.

Live activities

Live activities with Dynamic Island rules

A priority queue that never covers your work

Compact wings grow sideways inside the menu bar, 30–112 pt per side

Alerts of 8 s or less queue by priority; time runs only on screen

Preempted alerts resume; anything waiting 12 s is dropped

Persistent activities peek for 4 s, then rest in the wings

Bands render from source; key interception, banners and Bluetooth need a live check.

Speaker notes

The closed island follows Dynamic Island rules. Compact activities grow sideways inside the menu-bar height, so nothing below the menu bar is covered. Short alerts go into a priority queue whose clock only runs while they're visible, so a notification can't eat the charging alert. Volume and brightness are live feedback: newest wins and they're never replayed. Long-running things like a timer, a meeting or a recording peek in the band for four seconds and then tuck into the wings.

On-device AI

The on-device AI stack

Apple frameworks first; the network is opt-in

FoundationModels

dictation cleanup, summaries, replies, prompts, plans

Vision

OCR everywhere, face landmarks for Screen Distance

Speech

SpeechAnalyzer on macOS 26+, SFSpeechRecognizer fallback

Translation

TranslationSession cached per language pair

ScreenCaptureKit

stills for Ask Screen, SCStream audio for meetings

NaturalLanguage

language ID and entities for Spaces

Speaker notes

One constraint shaped the code: we build with the Command Line Tools only, and the @Generable macro plugin isn't part of them, so guided generation uses DynamicGenerationSchema built at runtime. The model has a 4096-token context, so meeting transcripts are chunked. Speech uses the new SpeechAnalyzer and SpeechTranscriber on macOS 26 and falls back to SFSpeechRecognizer. ScreenCaptureKit gives us stills with SparkV's own windows excluded, and an SCStream with capturesAudio for meeting audio, which is why no bot has to join a call.

Dictation · Meetings

Speech in, structured text out, on the Mac

Live Translation

AI in the loop

Translation order: Apple Translation → on-device model → Groq if allowed

Warm translation: 0.33–0.8 s per caption

Apple Translation latency, measured on macOS 27 (seconds)

Sources/Labs/LiveTranslation/DESIGN.md, measured on the development Mac

Speaker notes

Live Translation tries Apple Translation first, falls back to the on-device model when a language pair isn't downloaded, and uses Groq only if the user turned on that specific toggle. Cold sessions take two to three seconds; warm ones under a second per caption, which is why sessions are cached per pair.

Real offscreen renders from current source, sample data.

12

Private by default

Nothing leaves the Mac unless the user brings a key

On device: speech, camera, screenshots, clipboard, Spaces, meeting audio

Groq: per-feature toggle, off by default, the buyer's own key

While a toggle is off, the keychain is never read

Clipboard history starts off; concealed and transient copies are skipped

12 permissions, each asked only when the user clicks Allow

Speaker notes

The privacy model is simple to state and easy to audit. Speech, camera, screen captures, clipboard, Spaces and meeting audio stay on the Mac. Groq is the only cloud path, and it's opt-in per feature: Clicky, Tray AI, meetings, Live Translation, Flow Canvas and UI Audit summaries each have their own switch, default off, using the buyer's own key. When a switch is off the code doesn't even read the keychain item. Clipboard history is off until you turn it on, and it honours the pasteboard conventions password managers use to mark concealed or transient copies. Setup asks for nothing up front: each of the 12 permissions is requested only when you click Allow, and every feature works in a reduced way without it. License checks, when they ship, will send the key, an anonymous device ID and the app version to Lemon Squeezy, and nothing else. There are no analytics.

Developer agent · UI Audit

UI Audit: a QA agent for your own site

Playwright and axe-core, started from the notch

Swift spawns node audit.mjs: JSON lines out; pause, resume, stop in

Crawl, forms, axe-core WCAG 2.2 AA, 1440/390 px layout, Tab order

Origin allow-list; writes blocked off test hosts; risky clicks skipped

P copies a fix prompt for Claude Code, Cursor or Copilot

Started from the notch

Speaker notes

UI Audit audits websites you own. The Swift controller writes a run config, starts a Node runner with Playwright and axe-core, and talks to it over JSON lines: plan, page, step and finding events come out; pause, resume and stop go in. If the app dies, stdin closes and the runner stops, so you never leak a crawler. The runner crawls, checks layout at 1440 and 390 pixels, walks the Tab order, runs axe-core for WCAG 2.2 A and AA, and fills forms with type-correct test data. The safety model is strict: navigation outside the allowed origins is aborted, every non-GET request is blocked unless the host is local or test or you opt in for this run, and anything that looks like pay, delete or log out is never clicked. It needs Node 20 and Playwright's Chromium on the machine today.

Developer agent · Browser Flows

Browser Flows: record once, replay with data

Self-healing selectors; secrets are never stored

Each step stores ranked selectors and an element fingerprint

Healing accepts a match of 0.6 or more that clearly beats the runner-up

Passwords become {{password}}, asked at replay, sent over stdin

CSV loop: one replay per row, up to 500 rows

Self-test not yet clean under load: one replay timed out, one CSV loop hung. Fix before launch.

Speaker notes

Browser Flows records a browser task once and replays it. Each recorded step keeps an ordered list of selectors, in the spirit of Selenium IDE's targets list, plus a fingerprint of the element: tag, role, accessible name, text, attributes and ancestor path. When every selector fails, the runner scores all elements against the fingerprint and accepts the best one only if it scores at least 0.6 and clearly beats the runner-up, then writes the healed selector first. Password, card, CVV, OTP and SSN fields are never read: they become variables and are passed over stdin at replay, never on the command line. Flows that mention purchase, payment or delete need an explicit confirmation. Honest status: the recorder self-test isn't clean yet; under heavy load one replay timed out and a CSV loop hung. That's on the roadmap before launch.

Developer agent · Flow Canvas

Flow Canvas: workflows as a graph

Sources in, actions chained, run on this Mac

Drop links, PDFs, screenshots and notes as source cards

Chain extract, compare, summarize, report and chat-with-sources

"Suggest steps" plans the chain from one sentence

Export to Markdown, PDF, CSV, Tray, Notes or a Space

Speaker notes

Flow Canvas is a whiteboard for AI workflows. Source cards hold links, PDFs, screenshots or notes; action cards extract fields, compare, summarize or write a report; edges carry data between them, and Run all executes the graph. You can also describe the goal in one sentence and Suggest steps builds the chain. It ships with four templates, including the competitor pricing comparison you see here. The engine indicator top right says 'On this Mac': FoundationModels, Vision OCR and Apple Translation do the work. Groq is a separate opt-in for this feature only. Canvases are plain versioned JSON in Application Support, and dropped files are copied into the canvas's assets folder; originals are never moved.

Engineering

Engineering practices

A small toolchain and strict habits

CLT-only

one zsh build script, no Xcode project required

No macro plugins

no @State, #Preview, @Entry, @Generable

Temp-dir builds

iCloud can't modify files mid-compile

Stable signing

permission grants survive every rebuild

Hardened Runtime

explicit camera, mic, calendar, Apple Events entitlements

Real-source harnesses

Swift 5 and 6, private pasteboards

Speaker notes

We build with the Command Line Tools only. build.sh copies sources into a temp folder, compiles GlanceKit as a static library with its own concurrency settings, compiles the app, builds the Now Playing adapter framework with clang, signs nested code first and then the app with the Hardened Runtime. The temp folder exists because the project lives on iCloud Desktop, which touches files mid-build and adds Finder attributes codesign rejects. No Xcode means no macro plugins, so the code avoids @State, #Preview, @Entry and @Generable. A stable self-signed identity, 'NotchIsland Developer', gives every build the same designated requirement, so Accessibility and Screen Recording grants survive rebuilds.

Sandbox constraints: Business Plan §5.

19

Distribution

Shipping outside the Mac App Store

What the sandbox blocks, and the release pipeline we're adding

WHY NOT THE APP STORE

Accessibility APIs don't work in the App Sandbox

Event taps and CGEvent.post for fn, media keys and paste

Private DisplayServices and MediaRemote (via /usr/bin/perl)

Spawning Node, Playwright and /usr/bin/shortcuts

DEVELOPER ID PIPELINE (PLANNED)

01

Developer ID Application cert replaces the local identity

02

Sign nested code with --options runtime --timestamp

03

notarytool submit --wait, then stapler staple

04

Sparkle 2 updates with an EdDSA-signed appcast

05

Lemon Squeezy License API: activate, validate, deactivate

Speaker notes

SparkV can't be sandboxed. Apple's DTS says Accessibility APIs aren't compatible with the App Sandbox, and we also need event taps for the fn key, posted key events for paste, private DisplayServices for the HUD, the MediaRemote adapter for Now Playing, and child processes for Node and Shortcuts. NotchNook stays off the App Store for the same MediaRemote reason. So we ship direct: a Developer ID certificate replaces today's local identity, every nested binary is signed with the Hardened Runtime and a secure timestamp, the DMG is notarized and stapled, and Sparkle 2 delivers updates from a signed appcast. Since Sequoia, an un-notarized app can't be opened with right-click Open, so notarization isn't optional for a paid product. The local identity stays for development builds. Sources for the sandbox constraints are in the business plan, section 5.
